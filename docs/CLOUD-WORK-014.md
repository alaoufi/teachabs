# العمل والبناء من الهاتف دون إبقاء اللابتوب مفتوحًا

## ما تم تجهيزه

فرع مستقل: `codex/admin-cloud-build-014`، مبني على نسخة الإدارة
`6537b609441fbe4639c7d51c6cd0bee2b4cc2d5b`.
كل الإضافات محصورة في ملف البناء السحابي وأداة التحقق وهذا الدليل.
لم يتغير `main` أو فرع الإدارة الأصلي أو ملفات الفصل والسبورة، ولا يوجد PR أو نشر للخادم.

يبني GitHub Actions مشروع `admin-preview-android` المستقل، وليس تطبيق `android` الأصلي.
تُستخدم أداة Gradle الموجودة في `android/` للتشغيل فقط دون تعديلها.
المعاينة تحوي 19 شاشة وهمية للقراءة فقط، دون إنترنت أو بيانات حقيقية أو تسجيل دخول أو حفظ.
لا يحتوي الإعداد على عنوان خدمة خارجي أو أسرار أو مفتاح توقيع دائم.

## طريقة الاستخدام من الهاتف

1. يُحفظ التعديل المصرح به على هذا الفرع في GitHub. كل دفع جديد للفرع يشغّل بناءً سحابيًا.
2. افتح [عمليات البناء](https://github.com/alaoufi/teachabs/actions) في متصفح الهاتف وأنت مسجل بحساب GitHub.
3. افتح أحدث عملية بعنوان **Build offline administration preview**. لا تُنزّل إلا من عملية ناجحة للنسخة المطلوبة.
4. من **Artifacts** حمّل `admin-preview-...`، ثم فك الملف المضغوط وافتح ملف APK الموجود داخله على هاتف Android.
5. توجد معه بصمة SHA-256، هوية التطبيق، التوقيع، وبيان الملفات المضمّنة. يمكن إعادة البناء نفسه من **Re-run jobs** داخل عملية سابقة بصلاحية الكتابة.

الفرع معزول عمدًا. لا نعتمد على زر **Run workflow**: تشغيل `workflow_dispatch` المعتاد يحتاج ملفًا في الفرع الافتراضي، ولم نغيّر `main`.
لا يعمل هذا البناء من تحديث `main` أو فرع الإدارة الأصلي؛ يجب نقل التغييرات المصرح بها إلى فرع البناء أولًا.
لا تنفذ دمجًا واسعًا من `main`، حتى لا تدخل أعمال الفصل الأخرى دون قصد.

## حدود التوقيع والتجربة

- هذا APK تجريبي موقّع بمفتاح تصحيح مؤقت ينشئه عامل البناء. لا ننسخ مفتاح اللابتوب ولا نخزّنه في GitHub.
- تختلف مفاتيح التصحيح بين عمليات البناء؛ لذلك لا نعد بتثبيته كتحديث فوق ملف سابق. إذا رفض Android التحديث، احذف **تطبيق «الإدارة · معاينة» فقط** ثم ثبت المعاينة الجديدة. هذه المعاينة لا تحفظ بيانات مستخدم.
- لا تحذف تطبيق «خطوة» أو أي تطبيق آخر. هوية هذه المعاينة المستقلة هي `app.teachabs.adminpreview`.
- يشغّل البناء اختبارات الإدارة والمدرسة والمعاينة، ويؤكد التوقيع وهوية التطبيق وغياب الصلاحيات وبصمات الملفات ونسخة المصدر النظيفة. لا يدّعي تشغيل التطبيق على جهاز أو محاكي Android، ولا يشغّل مجموعة اختبارات الفصل داخل هذا المسار.
- أي توقيع ثابت مستقبلًا يحتاج ترتيبًا منفصلًا وموافقة قبل نقل مفتاح خاص أو إنشاء وصول دائم. لا تضع المفاتيح أو كلمات المرور في المستودع أو المحادثة.

## التكلفة والحفظ

- المستودع عام حاليًا. تشغيل عوامل GitHub القياسية للمستودعات العامة مجاني وفق [وثائق GitHub](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
- الإعداد يستخدم `ubuntu-24.04` القياسي، بحد 20 دقيقة وبناء واحد للفرع في الوقت نفسه. لا يفعّل خادمًا مدفوعًا أو عاملًا أكبر أو اشتراكًا أو تغيير فوترة.
- لا توجد ذاكرة تخزين مؤقت مرفوعة. ملف APK الصغير وملفات التحقق تُحفظ كـ Artifact مدة سبعة أيام. لا تعتبر Artifacts نسخة أرشيفية دائمة؛ حمّل ما تريد الاحتفاظ به قبل انتهائها، ويمكن إعادة إنتاجه من المصدر.
- إعدادات الفوترة والحصص الحالية للحساب لم تُفحص أو تُغيّر. راجعها قبل تحويل المستودع إلى خاص أو إضافة تخزين كبير أو خدمات مدفوعة.
- يبقى الكود والمولد وأداة البناء في GitHub حتى لو توقف الخادم التجريبي. نسخة الأساس محفوظة على `codex/admin-separation-010` وبصمتها الكاملة أعلاه. لا يوجد حذف للنسخ السابقة.
- GitHub العام ليس مكانًا لنسخ قواعد بيانات الحسابات أو الطلاب أو كلمات المرور. مصدر المعاينة يستخدم بيانات وهمية فقط. نسخ بيانات الخادم الحقيقية موضوع منفصل يحتاج تخزينًا خاصًا وآمنًا.

## تطوير الكود أيضًا دون اللابتوب

البناء السحابي لا يحتاج اللابتوب بعد حفظ المصدر. لإتاحة مهام تطوير طويلة في بيئة مستقلة عنه، المسار المقترح هو إعداد [بيئة برمجة سحابية](https://chatgpt.com/cloud-environments/new) للمستودع مرة واحدة من الويب أو تطبيق الكمبيوتر، واختيار فرع الإدارة الصحيح عند بدء المهمة.
بتاريخ 2026-11-06 لم تكن هناك بيئة برمجة سحابية محفوظة متاحة للحساب، لذلك لا ندّعي أنها أُنشئت أو أن مهامها تعمل بالفعل.
يجب أن تتضمن بيئة التطوير Node.js 24 أو أحدث؛ ويمكن ترك بناء Android لهذا الـ workflow بدل تثبيت SDK على كل بيئة.

GitHub Codespaces بديل محرر سحابي، لكنه ليس ضروريًا لمسار البناء ولا شُغّل هنا. لحساب GitHub Free الشخصي حصة 120 ساعة-نواة و15 GB-month؛ جهاز بنواتين يستهلك الحصة الزمنية بسرعة الضعف. قد تُحتسب رسوم بعد الحصة إذا كانت الفوترة تسمح، ويستمر احتساب مساحة التخزين أثناء وجود البيئة. [تفاصيل الحصص والأسعار](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces).

## الرجوع

يمكن تجاهل فرع البناء والعودة إلى فرع الإدارة الأصلي دون عكس أي تغيير في التطبيق أو الخادم.
إيقاف تشغيلات مستقبلية أو حذف ملفات البناء قرار منفصل؛ لا توجد عملية حذف تلقائي للمصدر أو للنسخ الاحتياطية.

## مراجع التنفيذ

- [تشغيل GitHub Actions يدويًا وحد الفرع الافتراضي](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow).
- [الأدوات المتاحة على Ubuntu 24.04](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md).
- كل Action مثبت ببصمة commit كاملة. لا يُقبل اتفاق SDK جديد تلقائيًا ولا يُشغّل `sdkmanager --licenses`؛ يجب وجود SDK 34 والأدوات مسبقًا وإلا يتوقف البناء.
- المولد واختبارات الإدارة يستخدمان مكتبات Node المضمنة؛ لا نثبت حزم npm ولا نغيّر ملف قفل تبعيات الفصل. كشف التشغيل الأول أن ملف القفل الحالي ينقصه بعض الحزم الاختيارية لمنصات أخرى، ولذلك فُصل تحقق المعاينة عنه دون تعديل المصدر المشترك.
